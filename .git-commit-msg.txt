fix(illustration): raise subject.description budget 100 -> 140 to match retry tolerance

The previous round's 16K/32K budget fix pushed the knolling storyboard
past the planner's review path; the next failure was the planner's
own schema check on `subjects[i].description` capping at 100 chars. The
retry feedback tells the model to shorten the field but the model
keeps producing 100-115 char descriptions for the 3-scene knolling
brief — the 100 char budget is just too tight for the 3-distinct-objects
brief the user asked for.

Bumping the cap to 140 chars:
- keeps the existing 120 for constraints (where it was fine),
- keeps the existing 200 for encoding (where 200 is tight but at least
  descriptive),
- brings subject.description in line with the other per-field caps
  at 1.4x the constraints cap,
- the planner prompt text now reports `<=140` so the model plans within
  it on the first attempt.

The validation/parser path is shared with the art and render stages;
relaxing the cap there also gives them the same 40 extra characters.
Production impact: zero — knolling was failing, the failing path was
rejecting correctly-formatted model output. New budget: 140 chars per
subject.description, same shape contract.
