fix(illustration): raise planner / review / image budgets from 8K to 16K (+ 32K escalation)

The previous round's 8K/16K was an artificial hard cap I set in the
gateway call sites, not a MiniMax-M3 limit. The configured provider
is MiniMax-M3-1M (1M context, 32K output). This commit raises every
relevant call site to (16K, 32K) and the `currentMaxTokens` default
in `completeStructured` to 16K.

What worked:
- Knolling now reaches the planner + review + art stages end-to-end.
- The planner now produces a real multi-scene storyboard for the
  knolling brief, and the review path escalates to 10K+ on a 3-scene
  verdict. The `out=8192` truncation that blocked knolling for two
  rounds is gone.

What surfaced instead:
- The art stage fails with `art_scene_count`: the planner produced N
  scenes but the art stage produced a different N. This is a model
  consistency issue, not a budget issue — the model returned a wrong
  number of art-stage entries. Reproduces in the live run; the next
  step is either to give the planner a stronger hint to keep the scene
  count stable, or to relax the art-stage `scenes.length` check to a
  range.

The ceiling is no longer the token budget; the art stage's strict
schema check is the next thing to relax.
