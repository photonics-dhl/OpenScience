独立 High 有界设计审阅已通过；审阅发现的旧公开页读取实时标题/作者/许可问题已补入实施范围。这是设计审阅结论，不是已部署修复或删除功能验收。

## 已确认的使用规则

| 对象或操作 | 产品行为 |
| --- | --- |
| 日常编辑、确认分析、整理图文 | 保存私有草稿，不消耗公开版本号 |
| 首次公开 | v1；再次主动发布更新为 v2，以此类推 |
| 修改已公开正文、图片或公开附件 | 先写入私有草稿；再次发布生成新版，即使只改错别字 |
| 整理私人笔记、会话、未公开材料 | 不改变公开版本 |
| 论文分析记录 | 从主页面移除；确认、重新分析和追问通过 Hermes 完成 |
| 发布历史 | 只展示已公开版本，未发布时不显示；撤回版本保留状态记录 |
| 编辑历史 | 放入“更多 → 编辑历史”，按时间和修改摘要展示，可恢复为当前草稿；不使用 vN |
| 删除范围 | 整项工作及其中的笔记、图片、分析草稿、Hermes 会话均可清理 |
| 删除会话 | 默认只删会话，保留其研究产物；可选同时删除未采用的生成内容 |
| 回收站 | 保留 30 天，期间可恢复或手动彻底删除；到期执行清除 |
| 公开成果 | 可从个人工作列表归档；撤回与删除私有内容分开，公开链接保留状态说明 |
| 公开版本引用的材料 | 保留该公开版本所需的副本或引用，不随个人空间清理丢失 |

用户确认这些规则不等于要求立即删除任何现存论文、文件或会话；实施功能时保留受保护的现存论文与产物。

## 代码事实与问题

- `packages/domain/src/research-object/sdf.ts` 用 `ResearchObject.version` 做编辑并发控制，保存时递增。它是内部修订号。
- `packages/domain/src/commit/commits.ts` 创建 `Version` 时直接令 `versionNo = ro.version`；`ingestion-service.ts` 确认分析会调用此路径，所以未公开稿也有编号，且编号可能跳跃。
- `packages/domain/src/publish/publish.ts` 沿用上述 `versionNo` 分配公开 ID。问题涉及发布模型及其消费者，不能仅把页面上的“版本”换成“草稿”。
- `apps/web/app/research-objects/[id]/edit/page.tsx` 同时渲染分析确认面板和内部版本列表；发布预览、媒体选择器、版本导航也直接显示内部编号。
- `apps/api/src/routes/research-objects.ts` 有更新/归档状态接口，未提供完整的删除、恢复、到期清除接口。已有归档不等于用户要求的回收站。
- `infra/schema.prisma` 中 RO → Version → Publication 存在级联删除关系；直接删除 RO 会危及公开记录。ManifestEntry 保存 artifactId 和 blobSha256，不能只靠数据库外键判断文件是否仍被使用。

## 版本语义与兼容策略

保留内部 UUID、并发修订号、提交与内容快照的职责。新增独立的公开序号语义，在成功发布的事务中分配；发布失败、重复请求、重新分析和日常保存均不得消耗新公开序号。复用现有发布事务、幂等和权限机制，不另造一套版本系统。

实施时明确唯一公开序号来源及其约束，再同步 API、公开 URL 解析、引用、导出、搜索/探索、策展、媒体链接和版本选择器。内部 versionId 继续绑定准确的正文和媒体，禁止通过“最新”把未公开内容混入公开页。

私有草稿是读取权限规则，不能只修改界面标签。RO 已有公开版时，当前 SDF、内部编辑历史、会话及未公开附件仍按授权范围读取；公开接口只返回对应已发布快照和其公开材料。实施须核对现有 RO 可见性判断，防止用整个 RO 的 public 状态暴露未发布修改。

公开版本的保留边界覆盖全部公开科研内容：标题、作者顺序/机构、贡献、许可及引用格式所需信息，以及正文、证据、图片和附件。当前 `apps/api/src/routes/research.ts` 仍读取 RO 当前标题、作者、贡献与许可；私人修改或清理可能因此改变旧公开版。实施应补齐既有发布快照缺失的字段/依赖，公开页、发布历史和导出读取对应版本；不另建平行快照系统。历史资料缺失时不得把今天的值冒称原始发布值，迁移须明确可恢复依据和兼容处理。撤回/限制等生命周期状态仍可按既有权限更新，不改写原科研内容。

兼容原则：一般既有公开编号和 URL 保留。2026-09-14 用户明确更正 deep-sub-cycle：唯一首次发布曾误用内部编号 v10，须行政勘误为 v1，同时补 DHL 署名；内部编辑序号、原发布时间及收据、科学正文/证据/媒体不改，也不新增一次发布。该误号 v10 仅在尚无真实第十次公开时以 307/no-store 临时导向规范 v1；真实公开序号优先，不能永久占用未来 v10。改前元数据和新增附件授权时间写入既有审计/record；没有发布记录的对象首次公开从 v1 开始。

当前第二篇 Quantization 的 `4266e4ed-9a89-45d8-8c0e-c6393bbc503d` 是内部发布候选快照，尚未公开；新规则落地后首次公开应显示 v1。保留该快照、已审正文及图片，无须重新生成。第一篇既有 `OSR-2026-000022/v/10` 保持有效。

恢复编辑历史会生成当前草稿的新状态，不覆盖历史记录、不改变已公开内容，也不自动发布。恢复可替换当前草稿，操作前给用户查看所恢复内容和影响；不需要暴露内部提交 ID。

## 工作台入口

主页面保留正文、附件、图文成果和 Hermes。移除“论文分析记录”；不丢弃它目前提供的待确认结果、来源选择、失败后续处理和重新分析能力，而是接入 Hermes 的对应对话与操作卡。已确认结果无需长期占据页面。

以“发布历史”替换当前内部版本列表，只列公开过的版本与发布时间/状态。编辑历史置于“更多”；材料已确认、草稿已保存等状态使用用户可读表达。内部编号、制作提示词与审校台账继续留给 Hermes，不重新引入正文。

发布后继续编辑时应明确“私有草稿”，并保留查看当前公开版和预览更新的入口。恢复历史稿或重新分析不能悄悄替换已公开版。

## 删除与恢复边界

删除首先移入回收站，普通列表、搜索、Hermes 活跃上下文均不再把它当成当前内容；回收站显示删除时间和剩余保留时间。恢复整项工作时恢复本次删除涉及的子项，不顺带恢复此前单独删除的内容。

删除会话的附加选项默认关闭；只有能由现有任务/采用关系明确判定为未采用、且未被其他有效内容引用的产物才可联动清理。不以创建时间、AI 自述或“未批准”状态推断“未采用”。有引用的项目保留并说明原因。

彻底删除必须同时处理产品可访问的正文、消息、搜索索引、解析/衍生文件和可恢复的私有历史；不能只隐藏卡片或将原文留在审计日志。必要审计只留操作事实。备份的实际保留和淘汰规则须在实施时核实，不能声称点击后所有备份立即抹除。

底层文件复用现有内容寻址存储。先解除可删除的私有引用，只有没有任何存续引用的内容才可物理清除；公开版本、其他工作和其他用户仍使用的共享内容不删除。不新增与现有存储重复的副本机制。

回收站状态与发布状态分开。删除权限按个人所有权及既有成员角色判断，不能把现有宽泛的状态更新接口直接当成删除权限。删除与发布、恢复、后台生成回写之间须按同一存续状态协调：已删除内容不能被迟到的任务结果自动恢复；删除不能与并发发布竞争掉被公开采用的材料。
