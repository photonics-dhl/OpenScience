# Industry / Investors 技术发现界面与内部架构

依据：2026-10-09 用户确认的服务对象方案及后续开发授权。仅扩展产业界和投资机构；高校与科研机构、期刊介绍页暂缓。执行状态、候选与验证见 [服务对象 CURRENT](../handoff/2026-10-09-researchers-services-handoff.md)。

## 页面与用户动作

| 页面 | 首屏 | 进入检索后的重点 |
| --- | --- | --- |
| Industry | 对话输入，灰色提示 `search any technology with AI`，需求/题名/DOI/arXiv 说明和可编辑示例 | 应用场景、性能要求、限制条件、来源结果与待验证问题 |
| Investors | 对话输入，灰色提示 `search any potential technology with AI`，可见 `Get in touch` | 关注领域、技术机会、已有依据、未知条件、带研究内容咨询 |

- 公开可浏览、整理需求与联系；执行文献检索沿现有登录与任务权限。登录只恢复输入，不自动发起检索。
- 输入/任务历史与来源结果连续呈现；宽屏并列，窄屏按阅读顺序排列。请求中防止重复提交，失败保留输入并提供恢复操作。
- 已选研究可进入有来源的比较清单、导出与联系上下文。证据缺失保留为未知，不从论文题名推测性能、成熟度、团队意愿或投资回报。
- 本轮提供本机草稿/资料导出，不宣称跨设备团队协作、自动订阅或正式技术评估已实现。

## 数据流和边界

1. 页面层仅收集用户需求、显示会话/来源、管理选择和联系草稿。
2. 状态层管理当前用户、受众、输入、精确检索任务、加载/失败/恢复状态；切换用户或受众隔离状态，过期响应不能回填新会话。
3. 检索适配层调用既有 `submitLiteratureAcquisition`、`getAgentTask` 与 `retryAgentTask`，复用服务端权限、配额、幂等和重试资格。默认提交 query，避免静默将元数据检索升级为全文获取。
4. 规范化层接收实际 `BrowserSourceRetrieveResult`，校验展示字段与外链；区分无匹配结果、上游不可用和部分来源失败。
5. 联系层只生成供用户审阅的咨询资料及邮件草稿；网页不代发邮件，也不记录“发送成功”。

现有真实生产者：`apps/api/src/routes/literature.ts` → `packages/domain/src/retrieval/literature-acquisition.ts` → `apps/agent-worker/src/retrieval/handler.ts` → `packages/domain/src/retrieval/browser-result.ts`。

- query 长度为 1–500 字符。服务端自行选择检索策略和来源，浏览器不传 Provider、凭据或检索权限。
- 当前浏览器结果提供 `id/provider/title/sourceUrl/identifiers/rights` 与可选临时文件信息；来源作者、摘要、实验指标等并未在此投影返回，页面不得伪造。
- 现有 query 检索不等于自然语言需求拆解或基于全文的 AI 技术分析。该阶段 UI 可以整理用户输入、组织元数据；来源解释和技术分析接入后才能呈现模型结论。
- 后续 AI 分析应在既有受控 Agent/Gateway 内执行，返回可定位的来源、结论与条件/未知项，由同一结果适配层消费。不得在浏览器直连模型或用固定文案冒称模型分析。
- 自动跟踪需要独立的用户订阅、取消和通知交付能力；团队/机构关联需要可靠归属信息。这些能力保持后续范围，不设置无实际行为的按钮。

## 联系方式

用户指定接收邮箱为 `chunanqing@opt.ac.cn`，集中配置并允许后续更换。联系表单包括姓名、机构、邮箱和咨询需求；用户可以审阅拟附带的研究链接。邮件草稿对主题和正文编码，点击后由用户在自己的邮件客户端确认发送；同时提供资料导出以供保存或手动发送。

## 验收范围

- 从站内服务对象菜单进入两个页面；桌面/手机与中文/英文的入口、输入、来源、比较及联系操作均可到达。
- 检索输入上限、真实生产者 DTO、空/部分/失败状态、外链协议、幂等恢复和账户隔离按本次变更定向验证。
- 联系草稿收件人、正文与所选来源正确；测试仅检查链接/导出，不真实发送邮件。
- 使用模拟 API 的成功交互与本机实际服务状态分开记录；生产检索或真实 AI 质量不能用模拟结果替代。
