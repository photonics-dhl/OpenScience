# 个人学术主页

## 需求依据与资料边界

用户于 2026-10-10 要求按 `OpenScience_个人学术主页_版式与全部文案_20261010.docx` 开发，同时沿用全站配色与字体、区分虚构示例与真实需求，并解释存储与网页的关系。原件只读，不进入代码仓库。本文记录产品取舍；实施和验证状态归 [服务对象 CURRENT](../handoff/2026-10-09-researchers-services-handoff.md)。

| 原稿内容 | 正式实现原则 |
| --- | --- |
| 顶部用途、左侧资料、右侧三张主卡 | 采用结构，使用全站导航、字体与颜色 token |
| 代表工作与贡献、当前关注与交流、更多了解我 | 采用栏目和固定界面文案 |
| 林知远、示例大学、工作履历、邮箱及十五条材料 | 全部为虚构演示，不自动填入任何真实账户 |
| 头像字、演示标识、示例材料弹窗 | 不作为正式数据字段或必经流程 |
| 三项工作、十五条材料、六种用途 | 示例数量，不是固定数量；已删除的空文案不补回 |
| 首屏摘要和详情正文不一致 | 属于示例改稿，不组合成真实经历；正式条目分别维护摘要和详情 |
| 编辑与发布流程待细化 | 为使主页可实际使用，补上最小编辑、私有保存、明确发布和撤下公开功能 |
| 早期展示自己的论文 | 需求继续有效；只能展示实际已公开成果，私有研究留在原管理入口 |

## 页面与交互

沿用服务对象 → Researchers → 管理我的学术主页的站内路径，保留其他服务对象和全站主导航。本人管理使用 `/me/profile`，公开作者地址为 `/researchers/<userId>`；原 `/me` 继续管理账户、身份和私有研究。登录后返回本人主页入口，不把账户身份选择等同于公开主页资料。

用户随后确认以“你的学术生态主页”为本人视角标题，公开页使用“学术生态主页”，副标题统一为“用来申请职位、寻求合作、招生招聘、成果传播。”；两层文字取代最初分散的用途列表。左侧显示作者主动提供的姓名、英文姓名、职务单位、团队、简介、ORCID 与可命名的其他个人主页链接。右侧三张卡纵向排列，同类条目在桌面横排；窄屏上下排列。正文自然延伸，不以固定高度裁切内容。

“代表工作与贡献”为核心，每个条目代表一项具体工作，允许平台搭建、实验室建设、软件工程化、科研组织和人才培养等，不要求必须有论文。分别记录工作成果、本人贡献、能力与经验、相关材料；首屏简短呈现，背景、过程和完整说明在详情展开。能力与经验由作者填写和确认，建议 3–5 项，不根据职称、上传者或论文署名自动推断。团队成果与本人贡献分开表达，不以论文署名代替个人职责。讨论中的博士生、专家、教授、博士后案例均为结构示例，不写入账户。

“当前关注与交流”表达招生、求职、招聘、合作或自定义意向，记录类型、具体方向／需求与联系入口；可关闭某项意向，保留作者资料而从公开展示中移除。仍通过保存和明确发布更新公开版本。资料为空时，访客不看虚构占位内容；本人看到明确的完善入口。

“更多了解我”采用三个入口：**团队**，灰字“可添加课题组/实验室主页”；**求学经历**，灰字“可添加课题组/团队/导师主页等”；**新闻/报道/会议...**，灰字说明可以添加线上课程、访谈、新闻报道、会议与视频链接。最后一个名称为用户唯一修正，不采用之前建议的“课程与媒体”。经历本身说明学校、阶段／时间等，再关联多个团队、导师链接；原简历与已公开论文入口继续保留。某条材料可以同时关联代表工作与更多了解我，不复制外部原文件。

工作、经历与材料列表采用可滚动弹窗，支持 Escape、遮罩关闭、键盘焦点约束与回焦。弹窗中的具体材料直接打开原始链接，不出现“这是一条示例链接”中间页。

ORCID 复用已有账号认证流程；手动填写网址不获得认证标识。公开标识必须与本人当前有效认证记录、所发布的网址匹配；认证记录不自动发布未选择公开的身份信息，也不代表平台认证了个人履历和贡献。连接前保护未保存编辑，认证后返回主页管理。

联系方式使用作者主动填写并决定公开的地址，不复用登录邮箱或平台咨询邮箱。页面不直接铺开邮箱，访客通过联系按钮查看。隐藏按钮不能保证阻止主动抓取，不能被称为邮箱保密机制。分享使用该作者的正式公开地址，排除编辑状态、查询参数及页内锚点。

## 存储与网页的关系

网页是一套可重复使用的排版；数据库保存每个人不同的资料。打开作者地址时，服务端按作者标识读取可公开资料，网页再把它们填入相同版式。用户修改资料无需重新编写或部署网页。

| 内容 | 保存位置 | 网页使用方式 |
| --- | --- | --- |
| 栏目、按钮、排版、颜色与字体 | 代码仓库及中英文资源 | 所有作者共用 |
| 姓名、简介、贡献、交流方向、经历、材料标题和网址 | OpenScience PostgreSQL 核心数据库 | 读取该作者明确发布的资料 |
| 未发布修改 | 同一数据库中的私有草稿 | 只有本人经登录后可读写 |
| 本人上传的小头像 | 当前版本限 256 KB 位图，编码后随资料存入数据库 | 仅在对应草稿或公开快照中显示，不上传外部图床 |
| 已发布主页 | 与草稿分离的公开快照 | 访客只读；保存新草稿不改变当前公开内容 |
| 原站论文、视频、代码、简历等 | 作者填写网址所指向的原网站 | 主页保存标题与链接，不自动复制原文件 |
| OpenScience 已公开研究 | 平台已有研究与公开版本存储 | 复用实际公开版本，不能读取私有工作稿 |
| ORCID 认证记录 | 平台已有学术身份凭证存储 | 仅用当前有效、匹配已公开网址的认证状态；不公开完整凭证 |

本机开发数据库、线上数据库和 GitHub 代码仓库是不同位置。提交网页代码不会上传用户资料，也不会自动升级线上数据库。本功能增加数据表时，正式上线需要沿现有迁移流程应用新增迁移；本地模拟响应不能证明生产已保存成功。

## 权限与验收

所有写入由已登录身份决定所有者，不接受客户端替换账户标识。私有资料不进入公开接口；发布操作只能复制本人明确确认的草稿。使用版本条件更新，防止多个标签页覆盖彼此修改。退出登录或切换账户后清除旧资料，忽略旧请求响应。

外链只接受 HTTP/HTTPS，不渲染任意 HTML，不由服务器抓取作者输入的任意网址。公开成果读取必须依据当前有效的公开记录及公开版本；撤下公开内容不得继续泄露旧草稿或标题。公开主页未发布、已撤下和不存在的情况保持一致的不可访问响应。

最小验证包含：站内入口和登录返回；保存后重新加载；未发布不可公开读取；发布后匿名访问；后续草稿不改变公开快照；撤下；过期版本冲突；跨账户隔离；不安全链接拒绝；工作详情与求学经历的键盘操作；分享地址；桌面及手机换行。新字段兼容旧草稿／公开快照；补验能力标签、关闭意向、三个补充入口、多条个人／经历链接及 ORCID 认证真伪与现有连接流程。实际数据库、接口合同测试、浏览器模拟和真实外部 OAuth 分别记录，不混称生产验收。
