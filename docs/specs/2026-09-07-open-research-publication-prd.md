# OpenScience 开放研究出版物 PRD

> 版本：v1.1；日期：2026-09-07；状态：用户授权实施，M1/M2 优先交付。
> v1.1 补充用户明确要求：每个 RO 提供 AI 友好的 API；阶段一确定合同，阶段二交付只读能力。
> 四阶段建设顺序来自用户确认的方向；本文件中的具体交互、门禁及目标值是供评审的开发要求。
> 本文作为既有需求基线的本轮增补，不表示功能已实现。用户已另行授权代码推送及部署；公开用户研究仍需研究发布授权。

## 1. 产品定义与目标

开放研究出版物是一个具有稳定身份、明确署名、可定位依据和不可变发布版本的研究对象。读者通过具体主张理解研究，通过原始材料核查研究，通过评审、复现及衍生工作接续研究。

产品承诺：每个结论可以追查依据，每次修改可以追查版本，每项贡献可以追查主体。AI 提取成功、表单填写完整或文件上传成功，均不能单独代表研究记录完整、科学结论正确或研究可复现。

底层继续采用 Research Object（RO）与 SDF。六字段承担研究叙述；Claim、Evidence、Artifact 与版本关系承担可核查结构。用户界面使用“结论、依据、原始材料、版本、评审”等语言。

每个 RO 同时提供人类可阅读的网页与 AI 可读取、引用和按权限调用的 API。网页与 API 读取同一份版本化研究记录。“每个 RO 有 API”通过统一服务和稳定对象地址实现，无需为每篇论文单独部署服务；私有 RO 的 API 仍仅对获授权主体开放。

### 1.1 用户与核心任务

| 用户 | 任务 | 成功结果 |
|---|---|---|
| 作者、获授权整理者 | 导入论文，核对提取内容，生成研究记录 | 原文、主张与确认内容进入同一可追溯版本 |
| 读者 | 理解发现，判断适用条件与证据缺口 | 从结论直接打开对应来源，区分报告、推断与解释 |
| 复现者 | 获取数据、方法与运行材料 | 知道可获得什么、缺少什么，并能提交独立复现记录 |
| 评审者、编辑、学术社群 | 针对具体版本提出评价 | 评价主体、范围、依据与作者回应清晰 |
| 科研 AI、外部开发者 | 按授权读取研究、追查依据并精确引用 | 无需抓取网页或重新解析 PDF，即可获得版本明确的结构化记录 |

### 1.2 首期边界

首期交付阶段一、二：可靠的论文导入、确认、版本绑定、来源核查与公开阅读闭环。发布须由有权限的用户明确发起；私有快照生成不自动公开。

阶段三发展解释体验，阶段四发展评价与接续研究。首期不承诺通用实验复现、任意代码运行、全自动科学审稿、法律优先权认证、整套期刊投稿系统或全学科高质量视频生成。

## 3. 核心内容合同

### 3.1 对象与关系

| 对象 | 必须表达的内容 | 约束 |
|---|---|---|
| RO | 稳定身份、研究标题、来源类型、作者与整理者 | 整理已发表论文不得把整理者列为原研究作者 |
| Draft | 可编辑内容、修订号、草稿材料、待确认建议 | 跨页面和跨设备恢复，不能依赖 URL 参数维持材料归属 |
| Claim | 陈述、类型、条件、限制、依据关系与推理说明 | 有稳定逻辑身份和版本化内容；同义改写不制造新贡献 |
| Evidence | 类型、原始定位、关系、提取来源及确认记录 | 支持、反驳、限定、背景须区分；来源存在不等于证明充分 |
| Artifact | 原始字节、哈希、类型、大小、许可与来源 | 同名不同内容不得混淆；原件不可被 AI 改写 |
| SourceMap | 文件页码、区域、文字及图表位置 | 只是定位中间产物；须被 Evidence 引用才形成可查依据 |
| Snapshot / Version | 确认内容、Claim、Evidence、材料和解释资产清单 | 一次创建一个完整不可变快照；发表另外记录可见性与发布时间 |
| PresentationAsset | 解释图、视频、模拟及其依赖和审核记录 | 不自动充当原始 Evidence，绑定所依据的版本和 Claim |
| Assessment | 评价者、目标版本/结论、依据、利益冲突、回应 | 独立追加；新评审不改写原出版快照 |

Claim 必须同时支持“这项研究主张什么”和“这份材料为何与主张相关”。AI 给出的依据关系须经确认；平台不能将机器置信度包装成科学真实性评分。

### 3.2 内容状态与可用性

状态采用独立维度：内容是否存在（有内容、原文未报告、不适用）、来源（原文、作者补充、整理者补充、AI 建议）、确认（待确认、已确认）、材料可用性（公开、受限、可申请、未提供）。

“原文未报告”须表示已检查的来源范围，不能由解析异常代替；“不适用”须有简短理由。“未提取到”先标待核查。局限和数据可用性不能只用一个可复现性长文本代替。

每篇研究建议凝练 3–7 条主要 Claim；不作为机械配额。允许一条主要结论、阴性结果和重复实验，不为满足数量拆句。方法和条件可作为下级内容组织。

### 3.3 引用、署名与语言

保留原论文 DOI、原作者、原出版时间和许可；单独记录平台接收时间、RO 整理者与 AI 辅助过程。元数据待核实时明确标注。平台接收记录不等于研究首次发现或权利认证。

支持精确引用 RO、某个公开版本及该版本内的 Claim。最新版本入口与固定版本入口须区分；新版本不得改变旧引用内容。中文和英文解释共享同一来源与版本，保留原文，译文注明生成和确认状态。

### 3.4 每个 RO 的 AI 友好 API

以下为目标接口形态，不是已有实现声明。M0 应审计并复用现有 API；具体路由可调整，但对象身份、版本语义、权限和返回合同必须一致。

| 示例接口 | 内容与用途 |
|---|---|
| `GET /api/ros/{id}` | 研究身份、作者、来源、许可、可访问版本索引及固定版本链接 |
| `GET /api/ros/{id}/versions/{version}` | 一个精确快照的研究叙述、关系索引、引用信息和完整性状态 |
| `GET /api/ros/{id}/versions/{version}/claims` | 主要结论、条件、局限、推理及支持/反驳/限定的证据引用 |
| `GET /api/ros/{id}/versions/{version}/evidence` | 原文、图表、数据和代码的获准元数据、定位及可用性 |
| `GET /api/ros/{id}/versions/{version}/manifest` | 文件清单、内容哈希、分项许可及授权获取入口 |

API 最低合同：

1. 返回明确的 `schemaVersion`、`objectId`、`versionId`、网页引用地址和关联资源链接；集合有分页与稳定顺序，不能静默截断后表现为完整结果。
2. RO 默认入口中的最新版本指最新已公开版本；未发表的私有 RO 仅向获授权主体返回其可访问快照。不得把可变草稿伪装为固定版本，也不得把新私有草稿作为公开最新版本。跨多个接口读取时先取得 `versionId`，后续请求固定该版本。
3. 内容字段明确表达未报告、未提取、未公开、不适用及待确认等状态；不能都用空字符串或 `null` 代替。无权获知的私有对象统一按不泄漏存在性的策略响应；只有允许公开的材料元数据才能标示“访问受限”。
4. Claim 与 Evidence 保留稳定 ID、固定版本、来源文件哈希、页码/区域和引用关系。机器置信度、人工确认状态与科学评价分别表达。
5. 网页、API 和导出对同一版本及同一权限范围返回一致事实。翻译或即时 AI 摘要不得悄悄替换正式版本原文。
6. 获准公开内容支持匿名只读访问并受合理限流；私有内容采用可撤销、最小权限的应用授权。读取权限不包含修改、发布或扩大可见性的权限。
7. Manifest 只返回获准公开的材料信息和稳定获取入口，不暴露存储内部路径或凭据。需要鉴权的文件在实际获取时重新检查权限；短期下载链接不作为永久引用。
8. 固定版本内容不可原地修改；访问策略、撤回/限制状态及临时交付信息可以变化，须与内容快照区分。缓存须遵守权限和撤回策略，私有响应不得进入共享公开缓存。
9. 发布机器可读的 OpenAPI 描述、响应 Schema、鉴权说明、错误码、分页/限流说明和最小调用样例；RO 页面提供“API / 机器可读数据”入口，避免要求调用方猜地址。
10. 只读 GET 不触发模型生成、草稿写入或收费任务。错误响应包含稳定错误码与是否可重试；限流提供重试指引。破坏性合同变更须升级接口或 Schema 并提供迁移说明。

后续操作 API：阶段三支持经授权创建修改建议及查询异步任务，阶段四支持提交评审或复现记录。写入必须复用身份、幂等、版本冲突和审批机制，不允许外部 AI 绕过作者确认直接改写正式版本或公开研究。MCP 可作为后续适配层，不替代首期 HTTP API，也不另存研究事实。

样板期望：AI 读取超快科学 0175 的固定 RO 版本后，可以区分论文报告的高光子数、损耗假设下的压缩估算和数据需向作者申请，并沿 API 提供的引用找到对应来源；不得因只读 API 返回成功而推断研究已经复现。

## 4. 完整用户流程

1. 用户选择或上传论文；系统识别标题、来源和工作空间，用户核对。已有材料提供复用或创建新研究的选择，不静默合并。
2. 文件安全存储后生成 Artifact 和服务器端 Draft 材料关联；后台解析可以重试，已上传原件不重复要求上传。
3. 展示提取的研究叙述、主要 Claim、对应证据候选及缺失项。用户可以逐条打开原文、修改、接受或拒绝。
4. 用户完成确认：所有条目有明确状态；没有材料的主张明确标注，错误证据不能默认接受。
5. 用户点击“确认并生成研究版本”。系统原子生成私有快照，绑定确认内容及材料关系；成功后显示精确版本、材料数量和待完善事项。
6. 概览、文件、来源和版本页面读取同一个所选版本；用户随时可回到可编辑草稿。
7. 用户选择“预览公开版本”，核对署名、许可、内容和缺口披露。经现有发布筛查和用户明确确认后发表。
8. 后续修改进入新草稿；再次发表生成新版本，旧版本保持可引用。评价、复现和衍生记录关联目标版本。

“自动保存草稿”不生成公开版本；“生成研究版本”不等于发布。现有单独提交动作可保留用于其他编辑场景，但导入用户不应为完成同一确认承诺再寻找第二个按钮。

## 5. 阶段一：保证研究记录成立

目标：用户能够得到内容、依据和原件关系一致的研究版本。优先级标记 P0 为该阶段必须项，P1 为后续增强。

| 需求 | 优先级 | 行为及验收 |
|---|---|---|
| R1-01 草稿材料持久化 | P0 | 刷新、关闭页面、普通编辑入口和另一已授权设备均能恢复同一原件；移除草稿引用不能删除其他版本的原件 |
| R1-02 结构化提取 | P0 | 同时产出叙述、Claim、Evidence 候选及定位；模型结构校验失败时保留原件与解析结果，显示待处理 |
| R1-03 显式缺口 | P0 | 提取 Data Availability、测量/估算差别、适用条件；缺失字段允许披露后确认，不要求填充虚构叙述 |
| R1-04 原文对照审阅 | P0 | 选中 Claim 可看到关联原文与页码；能修改依据关系、拒绝错误绑定；未确认项有明确清单 |
| R1-05 原子确认与快照 | P0 | 叙述、Claim、Evidence、材料清单、审核归属同时成功或同时失败；失败保留草稿，不显示成功版本 |
| R1-06 幂等与冲突 | P0 | 双击、超时重试只产生一个快照；他人修改造成冲突时显示差异，禁止覆盖未见修改 |
| R1-07 版本语义 | P0 | 内部草稿 revision 不显示为出版版本 vN；顶部、历史、引用和详情显示一致的正式版本号 |
| R1-08 精确错误与恢复 | P0 | 区分认证、上传、解析、模型和保存失败；提示可恢复动作，保留输入，网关健康不掩盖任务失败 |
| R1-09 来源身份 | P0 | 原论文作者、整理者、原 DOI、平台创建时间和许可分离保存；AI 转换不产生虚假作者归属 |
| R1-10 AI API 数据合同 | P0 | 冻结 3.4 节的对象、版本、缺失状态、证据引用、权限及 Schema 合同；验证固定版本可无损序列化，与网页共用研究事实 |

阶段一出口：样板论文无需数据库手工补记录即可生成快照；任何未有依据的 Claim 都明确披露；“有 SourceMap 但 Claim/Evidence 均为空”的情况不能被标记为结构化研究完成。

## 6. 阶段二：保证读者能够核查

| 需求 | 优先级 | 行为及验收 |
|---|---|---|
| R2-01 结论入口 | P0 | 概览展示主要结论、条件和限制；每条结论可展开“为什么这样说”，关联依据与推理 |
| R2-02 精确来源 | P0 | 从结论两次以内操作到原 PDF 对应页和高亮区域；标明页码、来源文件和固定版本 |
| R2-03 定位降级 | P0 | 坐标不可靠时显示原页及未精确定位状态，不伪造高亮；扫描件无文字层仍可显示原页 |
| R2-04 材料一致 | P0 | 概览、编辑、文件、版本详情和下载清单引用同一数据关系；已绑定原件可查看，页面明确当前草稿或版本 |
| R2-05 权限与可用性 | P0 | 私有原件、派生图块、临时链接均检查权限；受限来源保留可公开元数据与缺口，不泄漏全文 |
| R2-06 公开预览与引用 | P0 | 预览呈现匿名读者实际可见内容；按既有审核后明确发布；引用固定版本，缺口和撤回说明可见 |
| R2-07 导出与完整性 | P0 | 授权导出包含所选版本内容、关系及可分发文件的哈希清单；离线可读，受限文件仅含获准元数据及缺失说明 |
| R2-08 变更定位 | P1 | 比较版本时展示结论、条件、依据和附件变化，不能只比较整段文本 |
| R2-09 每 RO 只读 API | P0 | 交付身份、固定版本、Claim、Evidence 和 Manifest 的可寻址接口；公开/授权私有访问、分页、限流和错误语义符合 3.4 节 |
| R2-10 AI 接入文档与发现 | P0 | 提供 OpenAPI、Schema、鉴权和调用样例；每个 RO 页面可找到 API 入口；外部客户端可固定版本完成结论到来源核查 |

阶段二出口：未参与整理的读者可以从三条样板结论找到正确依据，判断数据可用性，并引用准确版本；页面切换不改变来源归属。独立客户端只凭接口文档即可读取同一研究并完成相同核查，无需抓取网页；网页、API 与导出事实一致。

## 7. 阶段三：发展解释体验

| 需求 | 优先级 | 行为及验收 |
|---|---|---|
| R3-01 机制图 | P0 | 从已确认 Claim 生成解释草稿；展示系统构成和作用过程，保留原图入口，生成图明确标注 |
| R3-02 交互类型 | P0 | 区分概念示意、公式计算、实验数据重绘和独立复算；缺原始数据时不能称实验重放 |
| R3-03 Hermes 情境讲解 | P0 | 读取当前版本及选中结论；回答附可打开来源，材料不足时说明；即时回答不修改正式内容 |
| R3-04 内容依赖 | P0 | 解释资产关联 Claim 修订和版本；依据改变后在新版本标待复核，旧版本资产保持原状 |
| R3-05 生成与审核 | P0 | 展示范围及预期用量，生成失败不自动重复收费调用；确认后的资产才能进入正式阅读视图 |
| R3-06 视频与声音 | P1 | 场景关联结论及依据；字幕可读、手动播放、有静态替代；语音转写确认后复用文字编辑路径 |

样板：双 BBO 机制图展示泵浦、晶体间距和滤波；交互可解释模式选择，但不得编造未公开的实验采样点。Hermes 必须区分“光子数报告”与“损耗假设下的压缩估计”。

阶段三出口：读者能够说明图示解释什么及其依据；模型调用失败不影响正文阅读；结论更新不会让旧解释未经复核进入新发表版本。

## 8. 阶段四：连通评价与接续研究

| 需求 | 优先级 | 行为及验收 |
|---|---|---|
| R4-01 锚点评价 | P0 | 对指定版本、Claim 或 Evidence 提交评审/质疑；记录主体、范围、依据、利益冲突和日期 |
| R4-02 回应与修订 | P0 | 作者回应关联评价；修订列出解决、部分解决和未解决事项；旧评价不自动继承到新版本 |
| R4-03 复现记录 | P0 | 区分原结果复算、独立实验复现与解释模拟；记录环境、输入、输出及偏差，声明不等于平台验证 |
| R4-04 衍生研究 | P0 | 创建独立 RO 并记录来源版本、复用对象和贡献，保留许可约束；不得自动授予原材料权限 |
| R4-05 贡献归属 | P0 | 原作者、整理者、复现者、评审者、纠错者分别记录，不用点赞或平均分替代科学评价 |
| R4-06 组织与期刊 | P1 | 支持认证组织推荐和可携带评审记录；转投需作者授权，首轮不建设完整期刊投稿后台 |

阶段四出口：完整走通一条“针对结论的质疑、回应、新版本、评价适用性提示”和一条“复现/衍生关联”旅程。

## 9. 页面职责

| 页面 | 首要任务 | 关键状态 |
|---|---|---|
| 研究桌面 | 开始、继续、处理待办 | 失败任务与待确认事项可直接进入 |
| 导入 | 材料存储与解析进度 | 文件已存储、解析中、需处理、可审阅，分别反馈 |
| 审阅 | 核对主张和来源 | 原文、建议、差异、缺口与确认同屏或可直接展开 |
| 研究概览 | 理解研究及其边界 | 核心发现优先；就近查依据，不显示内部调试术语 |
| 文件与来源 | 查看既有材料、来源和使用条件 | 已绑定材料、待绑定材料、受限材料明确区分 |
| 编辑与版本 | 修改草稿、生成快照、追溯变化 | 保存、提交、发布是不同动作，编号一致 |
| 公开阅读 | 理解、核查、引用 | 不依赖作者工作区权限；声明、版本及证据缺口可见 |
| Hermes 侧栏 | 当前对象的解释与建议 | 不遮挡正文，不把页面任意错误转成助手整体失败 |

延续已确认的浅色低彩度工作区、原有 Wanko/神灯身份和稳定导航。阅读侧允许较宽图解与逐层展开；不要求每篇研究配视频，不以动效取代证据。

## 10. 数据一致性、兼容与技术交付约束

1. 优先复用现有 IngestionTask、AgentTask、Artifact、ClaimNode、EvidenceRecord、Version、Manifest、SourceMap、AI Gateway 和发布审核；先核对现有 API 能力，再决定新增接口。
2. Draft 到 Snapshot 的确认命令携带预期修订号及幂等键。引用对象必须属于授权工作空间/RO，文件哈希可核验，禁止跨租户关系。
3. 对象存储不能参与数据库事务时，先完成内容存储，再事务写入关系；关系失败的临时对象按现有受控回收机制处理，不返回部分成功快照。
4. 版本关系使用精确版本化标识。逻辑 Claim 的修订映射支持追踪，不能让可变记录影响旧快照。源文件替换后，旧定位不得无提示复用。
5. 文本完整不作为结构完整的替代指标。缺口披露进入清单；技术不完整与科研材料未公开分别处理。
6. 既有 RO 兼容阅读：显式显示“尚未整理结论与证据”，允许生成待确认升级草稿。不得向旧公开版本补写关系或追溯伪造用户确认。
7. 对今天的样板 RO，后续修复生成升级草稿并经确认创建新版本；保留已提交历史，不能直接改写以制造验收通过。
8. 默认复用 CPU 环境和既有沙箱；本 PRD 不要求新模型、GPU、依赖或网络暴露。来源全文和用户材料只能按现有授权路径进入模型。
9. 保存、生成快照和发布日志只记必要操作元数据；原文、令牌、私有提示词及临时凭据不得进入公开报告。
10. 阶段发布保留既有构建、迁移、运行时、权限和生产健康门禁；数据库迁移优先向后兼容，不以回滚删除已产生的用户数据。

## 11. 验收计划与目标

以下是待建立基线的目标，不是已经达成的数据。正式测试报告记录样本、版本、人工介入及失败，不以单篇成功推断总体质量。

| 测试组 | 最低验证内容 | 通过标准 |
|---|---|---|
| 内容正确性 | 10 篇获准使用的论文，覆盖双栏公式、扫描页、表格、缺数据声明和无独立局限章节 | 已确认关键结论和数值逐项对照；无伪造依据；缺失/不适用可如实提交 |
| 样板回归 | 本次超快科学 PDF，含光子数、波长、140 fs、42 cm、模式数及损耗假设 | 局限与数据声明可提取或明确提示人工核对；不能再静默遗漏 |
| 定位与关系 | 样本主要 Claim 到 Evidence、Artifact、页码/区域及版本 | 所有标为精确定位的项可核验；定位失败显式降级，不显示错误高亮 |
| 稳定性 | 双击、请求超时、断网恢复、后台失败、并发编辑 | 无重复版本、静默覆盖或附件丢失；可恢复到原草稿 |
| 版本与导出 | 创建两个快照，修改一条结论和一份材料，读取旧版本 | 旧内容/哈希不变；新旧差异准确；导出清单校验通过 |
| 权限 | 授权用户、另一工作空间用户、匿名读者 | 私有材料与派生证据均不泄漏；获准公开内容可读取 |
| AI API 合同 | 独立客户端按文档读取 RO、固定版本、Claim、Evidence、Manifest，遍历分页 | Schema 校验通过；版本和引用可解析；集合无静默遗漏；与网页及导出内容一致 |
| AI API 状态与权限 | 缺失字段、未公开数据、私有草稿、撤销授权、限流和受限材料 | 状态语义准确，不泄漏私有对象存在性或正文；GET 不写入或触发模型；重试指引明确 |
| AI API 版本稳定 | 读取期间发表新版本，再读取已固定的旧版本；检查最新入口 | 固定版本不漂移、不混入新关系；公开最新入口不暴露私有草稿；快照哈希不变 |
| 使用体验 | 至少 5 位未参与实现的研究人员 | 至少 4 位在 90 秒内指出主要结论和一个限制；两步内打开依据 |
| 跨端 | 中文/英文、桌面 1440px 和手机 390px、键盘导航 | 无主操作遮挡；原图比例保留；缺口与错误可见 |

记录指标：导入到首份可审阅结果耗时、无人工补写的结构提取完成率、用户核对耗时、缺失声明召回、来源定位正确率、快照创建成功率、重复提交数、附件关系丢失数。安全和关系一致性错误零容忍；模型质量与耗时先建立基线，再冻结 SLO。

## 13. 风险与待评审决策

- 解析器覆盖不全可能造成“原文未报告”误判：必须区分提取失败、待人工核查与已确认未报告。
- 错误来源关联比没有关联更具误导性：精确定位与证据支持关系分别审核，保留反驳和限定关系。
- 核心 Claim 缺公开依据时，建议允许明确披露后发表，但不授予“证据完整”状态；是否需要最低门槛由产品/编辑政策评审。
- 本 PRD 建议导入确认直接生成私有快照；是否仍需独立草稿确认步骤，应在 M0 用交互样稿确定，不能重复承诺创建版本。
- 整理已发表论文的公开规则、作者认领和纠错流程需确定；不自动将来源作者注册为平台用户。
- 公开发表不得继承“走测试流程”的泛化授权；验收使用明确获准的测试研究或保留私有状态。
- 解释资产复核和评审扩展会增加作者负担：首期只要求研究记录与来源核查，媒体和组织认证按需启用。
