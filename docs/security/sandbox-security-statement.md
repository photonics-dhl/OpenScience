## 1. 安全承诺 (Security Commitment)

OpenScience 致力于为用户提供安全、可靠的 Python 可视化沙箱环境。我们实施了多层安全防御措施，确保用户提交的代码在受控环境中执行，不会威胁平台或其他用户的安全。

### 1.1 我们做了什么

**网络隔离**：
- 所有沙箱容器完全禁止网络访问（`--network none`）
- 无法访问公网、内网、或云元数据服务
- 即使代码尝试导入网络库（如 `requests`, `urllib`），也无法建立任何连接

**资源限制**：
- 每个任务限制 1 CPU 核心、1 GB 内存、30 秒超时
- 输出大小限制 1 MB，超出自动截断
- 进程数限制 64 个，防止 fork 炸弹攻击

**文件系统隔离**：
- 容器根文件系统只读，无法修改系统文件
- 临时目录 `/tmp` 限制 100 MB，且禁止执行二进制文件
- 无法访问宿主机文件系统或其他容器数据

**权限隔离**：
- 容器内以非 root 用户（UID 1000）执行
- 无法提升权限（`sudo`, `su` 不可用）
- 无法访问 Docker socket 或创建新容器

**容器生命周期**：
- 每次任务创建全新容器，执行完成后立即销毁
- 不复用容器，防止数据污染或持久化攻击

**审计与追溯**：
- 所有沙箱作业记录在不可变审计日志中
- 记录用户 ID、workspace、脚本内容、执行时间、结果状态
- 支持安全事件回溯分析

###  1.2 基线安全测试

我们维护 16 项自动化安全测试，覆盖：
- **网络隔离** (3 项): 公网/云元数据/内网访问
- **资源限制** (3 项): 内存/输出/超时
- **文件系统** (2 项): 只读根 FS / /tmp noexec
- **容器逃逸** (4 项): Docker socket / 特权提升 / capabilities / 设备节点
- **策略绕过** (4 项): 动态导入 / Base64 / 字符串拼接 / 库漏洞

所有测试在 CI 中自动执行，生产部署前手动验证。测试代码公开在 `apps/science-worker/test/` 目录。

## 2. 用户责任 (User Responsibilities)

### 2.1 禁止行为

用户**不得**使用沙箱执行以下操作：

❌ **尝试突破沙箱限制**：
- 尝试访问网络、修改系统文件、提升权限
- 尝试容器逃逸、旁路攻击、时序侧信道攻击

❌ **恶意资源耗尽**：
- 故意提交大量并发任务耗尽系统资源
- 提交无限循环或恶意计算脚本影响其他用户

❌ **上传恶意代码**：
- 提交含有后门、木马、病毒的脚本
- 尝试利用已知 CVE 漏洞攻击容器或宿主机

❌ **侵犯隐私**：
- 尝试访问其他用户的数据或作业结果
- 通过 API 漏洞绕过 workspace 隔离

### 2.2 合法使用

用户**应当**：

✅ 仅提交用于科学可视化的合法 Python 脚本  
✅ 遵守平台使用条款和配额限制  
✅ 如发现安全漏洞，通过负责任披露流程报告（见 §4）  
✅ 理解沙箱无法 100% 保证安全（见 §3 残留风险）

## 3. 免责声明 (Disclaimer)

### 3.1 沙箱安全限制

尽管我们实施了多层防御措施，但**沙箱无法提供绝对安全保证**。以下风险无法完全消除：

**容器逃逸风险**：
- Docker, runc, containerd, 或 Linux 内核的 0-day 漏洞可能导致容器逃逸
- 一旦发生容器逃逸，攻击者理论上可获取宿主机权限
- 我们会及时更新 Docker 版本并监控 CVE 通知，但无法预防未公开漏洞

**资源竞争**：
- 在高并发场景下，恶意用户可能影响其他用户的作业性能
- 我们通过配额和限流缓解，但无法完全杜绝

**策略绕过**：
- 当前策略检查为简化版黑名单，可能被代码混淆绕过
- 即使绕过策略，沙箱容器限制仍生效（深度防御）

**时序侧信道**：
- 攻击者可能通过测量脚本执行时间推断系统状态
- 我们通过限制并发缓解，但无法完全防御

### 3.2 责任限制

**平台不承担以下责任**：

1. **用户提交恶意代码的后果**：
   - 如用户故意尝试攻击沙箱，导致账号封禁、法律追责，责任由用户自负

2. **第三方漏洞导致的数据泄露**：
   - 如 Docker / Linux 内核 0-day 漏洞导致容器逃逸和数据泄露，平台不承担赔偿责任
   - 我们会尽最大努力及时修复，但无法预防未知漏洞

3. **不可抗力事件**：
   - 云服务提供商故障、网络攻击、自然灾害等导致的服务中断或数据丢失

4. **用户数据安全**：
   - 用户应自行备份重要数据
   - 平台不保证沙箱作业结果的永久存储（默认 24 小时 TTL）

### 3.3 最大赔偿限额

如因平台安全漏洞导致用户数据泄露或损失，**平台的最大赔偿责任不超过用户过去 12 个月支付给平台的费用总额**（免费用户为 $0）。

## 4. 安全漏洞报告 (Responsible Disclosure)

我们欢迎安全研究人员负责任地披露安全漏洞。

### 4.1 报告流程

1. **发送邮件**: security@openscience.example.com（**待替换为真实邮箱**）
2. **提供信息**:
   - 漏洞类型（容器逃逸 / 越权访问 / DoS / 等）
   - 复现步骤（PoC 脚本或详细描述）
   - 影响范围（是否影响其他用户数据）
   - 建议修复方案（可选）
3. **保密期**: 请在报告后 **90 天内** 不公开披露，给我们时间修复
4. **致谢**: 修复后我们会在安全公告中致谢（如您希望）

### 4.2 奖励计划

当前暂无漏洞赏金计划。我们会根据漏洞严重程度提供：
- **致谢**: 在安全公告和致谢页面列名
- **荣誉**: 授予 "Security Contributor" 徽章
- **奖励**: 高危漏洞（容器逃逸/数据泄露）可能获得现金奖励（待定）

### 4.3 不被视为漏洞的情况

以下情况**不被视为有效漏洞报告**：

❌ 策略检查被绕过（如动态导入），但容器限制仍生效  
❌ 时序侧信道（已知风险，见威胁模型文档）  
❌ DoS 攻击（通过正常 API 提交大量作业，已有配额限制）  
❌ 社会工程学攻击（钓鱼、伪造邮件等）  
❌ 物理访问宿主机（需要合法物理访问权限）

## 5. 生产环境安全增强

在正式对外开放生产环境前，我们将完成以下安全增强：

### 5.1 基础设施

- [ ] **独立 ECS 部署**: 沙箱 worker 与数据库物理隔离，避免容器逃逸后直接访问数据库
- [ ] **容器镜像扫描**: 使用 Trivy / Clair 扫描基础镜像，确保无已知 CVE
- [ ] **监控告警**: 
  - 沙箱作业失败率 > 10% 告警
  - 容器创建失败率 > 5% 告警
  - Docker daemon CPU/内存 > 80% 告警

### 5.2 策略增强

- [ ] **P1E-3 AST 引擎**: 完整 Python 抽象语法树分析，检测语义级违规
- [ ] **并发数限制**: 单 workspace 最多 5 个并发容器
- [ ] **队列优先级**: 防止恶意用户提交大量作业影响正常用户

### 5.3 定期审查

- [ ] **季度渗透测试**: 聘请第三方安全团队执行
- [ ] **月度威胁模型更新**: 跟进最新 CVE 和攻击手法
- [ ] **年度安全审计**: 外部审计师审查代码和基础设施
