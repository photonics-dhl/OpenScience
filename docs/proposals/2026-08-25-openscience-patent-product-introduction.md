# OpenScience 产品与技术方案介绍

## 专利技术交底用途

**文档版本：** 1.0  
**编制日期：** 2026 年 8 月 25 日  
**产品名称：** OpenScience  
**产品定位：** 面向 AI 时代科研活动的研究对象管理、证据组织、版本演化、协作审阅与公开验证基础设施

> 本文帮助专利代理人理解产品、系统结构、关键流程和可拆分的技术方案。文中技术点不等同于权利要求，也不预先判断新颖性、创造性或可专利性。正式申请前仍需结合现有技术检索确定保护主题和申请组合。

## 1. 产品概述

OpenScience 将科研成果从一次性论文文件改造为可验证、可协作、可持续演化的研究对象。一个研究对象长期保有同一身份，内部同时容纳研究问题、洞见、方法、结果、局限、可复现性说明、数据、代码、图像、版本、审阅意见、许可和公开记录。研究者可以从零创建，也可以导入已有材料；Hermes 将材料整理为结构化草稿，但事实确认、版本保存、权限变化和公开发布始终保留人工决定边界。

产品基本闭环为：

`创建研究对象 → 导入或录入材料 → Hermes 生成结构化草稿 → 人工核对证据 → 保存不可变版本 → 协作与审阅 → 发布 OpenScience preprint → 社区验证与继续演化`

## 2. 用户与场景

主要用户是论文草稿、实验数据、代码、图像和讨论记录分散在不同工具中的个人研究者及小型研究团队。扩展用户包括外部审阅者、复现实验参与者、期刊策展编辑、机构管理员和公开读者。

典型场景包括：

1. 从空白六字段创建研究对象并保存首个版本。
2. 导入 Markdown、LaTeX、PDF、DOCX、图片、数据或代码，由隔离解析任务生成带来源的结构化建议。
3. 逐条接受、改写或拒绝 Hermes 建议，模型输出不能直接覆盖已确认内容。
4. 团队围绕同一对象创建 issue、分支和合并请求，意见绑定具体版本、字段或材料。
5. 作者发布早期版本，后续通过新版本补充结果或更正局限；旧版本保持可引用和可核验。
6. 公开读者先阅读研究叙事，再按需检查来源、差异、许可、讨论和复现实验记录。
7. 策展编辑将既有研究对象收入专题或期刊集合，不改写对象身份，也不把策展选择冒充同行评审结论。

## 3. 产品叙事与原则

OpenScience 建立在三个判断上：研究成果不是结束于投稿时刻的静态文件，而是具有身份、证据和版本历史的持续对象；AI 可以帮助整理、提示和比较，但不能替研究者确认事实；公开科研既要让人读懂，也要让人知道内容从哪里来、经过哪些修改、由谁确认、如何复现。

- **对象先于页面。** 页面只是研究对象在创建、编辑、审阅和公开阶段的不同视图。
- **证据先于自动完成。** AI 建议保留输入范围、来源片段、提供方、模型、时间和确认状态。
- **版本先于覆盖。** 已发布版本不被静默回写，修改通过下一版继续演化。
- **人工决定先于代理执行。** 写入、删除、合并、权限和发布先展示影响范围并取得确认。
- **阅读与验证并存。** 普通读者可以连续阅读，专业用户可以继续检查证据、版本、代码和数据。

Hermes 是这套叙事的角色化入口，不是装饰性聊天机器人。它在 Dashboard 提醒当前任务，在导入阶段说明数据处理，在编辑阶段指出缺失证据，在审阅阶段保持安静，在用户明确调用时提供研究动作或陪伴动作。

## 4. 系统总体结构

| 层级 | 主要组成 | 责任 |
|---|---|---|
| 用户界面层 | Web 应用、公开研究页、研究工作区、Hermes | 呈现研究流程、证据、版本和审批状态 |
| 接口层 | Fastify API | 身份、工作区、研究对象、材料、版本、协作、审批、发布和沙箱接口 |
| 领域层 | RO、SDF、权限、版本、协作、审批、发布模块 | 维持业务规则和状态转换 |
| AI 协调层 | AI Gateway、Agent Worker、Hermes 任务 | 统一模型调用、记录调用信息、执行提取与审阅任务 |
| 解析与执行层 | Document Parser、Science Worker | 隔离解析文档；在受限沙箱运行科研脚本并收集输出 |
| 数据层 | PostgreSQL、Redis、对象存储 | 保存元数据、状态、队列、版本清单和二进制材料 |
| 运维与审计层 | 日志、审计、配额、备份、不可变发布 | 追踪操作、限制资源、恢复数据并确认运行版本 |

系统按工作区隔离对象和成员权限。公开内容使用长期公开标识，内部数据库标识不承担长期引用。API、异步任务和前端共同使用同一对象身份、版本和审批记录，避免 AI 任务产生无法追溯的独立写入。

## 5. 研究对象、SDF 与材料

研究对象是平台核心聚合实体，包含长期身份、标题、作者和机构、工作区、可见性、草稿、版本序列、SDF、Artifact、协作关系、审阅、许可和发布时间记录。

SDF 将研究内容组织为六个稳定节点：Problem 记录研究问题和前提；Insight 记录关键认识或主张；Method 记录方法、条件和步骤；Results 记录结果和观察；Limitations 记录局限、风险和适用边界；Reproducibility 记录数据、代码、环境、依赖和复现步骤。

字段不仅保存正文，还保存来源片段、来源材料、模型与提示模板版本、缺失或推断状态、人工确认状态和最后修改者。界面明确区分已确认、待确认、缺失和推断，防止模型补全被误读为研究事实。

Artifact 承载论文、笔记、图片、视频、数据、代码和运行输出，记录所属对象、关联 SDF 节点、类型、来源、创建方式、时间、版本、许可、内容哈希和替代文本。AI 生成内容额外记录生成器、模型、提示或脚本。

## 6. 从材料到结构化对象

用户选择空白创建或材料导入。空白创建直接进入六字段编辑；材料导入先在本地编排文件，用户确认材料范围、用途、保存位置和处理方式后才创建解析任务。

Markdown 和 LaTeX 可确定性解码。PDF、DOCX 和 OCR 进入独立 Document Parser；解析进程无网络、无生产 Secret，以非 root、只读文件系统和受限内存、进程数运行，仅通过受控任务目录交换输入和结果。超限、格式异常或解析失败进入明确的阻断或人工复核状态。

Agent Worker 经 AI Gateway 生成 SDF 建议。Gateway 记录模型路由、提供方和调用信息；Hermes 保存输入范围和来源片段。建议进入待确认区，不直接覆盖正文。用户逐字段比较建议、证据和现有内容，可接受、编辑或拒绝；写入携带版本条件，避免并发覆盖。

## 7. 版本、差异与引用

草稿允许持续编辑和自动保存。保存版本时，系统根据 SDF、Artifact、权限和许可生成确定性清单与不可变快照，并计算字段、材料、作者、许可等多类差异。

长期对象身份与具体版本身份并存。引用者可以引用持续对象，也可以引用不可变版本；复现实验和正式论文适合引用具体版本。新版本不回写旧快照，撤回、争议或更正通过状态和后续记录表达，历史仍可审计。

## 8. 协作与审阅

工作区提供 Owner、Editor、Reviewer 和 Viewer 等角色模板，通过权限矩阵控制读取、编辑、审阅、合并和发布。单人研究默认线性草稿；出现并行实验或外部贡献时再建立分支和合并请求。

Issue、评论、审阅和合并请求可以锚定研究对象、版本、SDF 字段或 Artifact。合并前展示差异和影响范围，合并结果形成新版本候选。审阅保留提交、回应、解决或保留争议的过程，不以无痕删除代替处理记录。

## 9. 发布、许可与公开验证

发布前检查分为最低条件和建议完善项。最低条件包括标题、作者、可见性、版本号以及至少完成 Insight 和 Method；结果、局限或复现信息不足时可以早期公开，但必须显示尚未报告或缺失状态。

平台使用条款与成果再利用许可分离。作者未声明开放许可时，平台支持阅读、引用、评论、审阅和版本链接，但不自动授予外部转载、改编或商业利用权。许可变化创建新版本，不回写旧版本。

公开研究页先呈现标题、作者、研究对象 ID、版本、状态、许可和核心洞见，再呈现六节点研究叙事；证据、文件、版本、讨论、审阅和引用记录按需展开。Ultrafast Science 等策展层在对象之上附加卷期、栏目、编辑说明和精选日期，不改变对象身份，也不等同于同行评审结论。

## 10. 可复现实验与受控计算

Science Worker 在无网络、无 Secret、非 root、只读基础环境和资源上限下运行经过策略检查的科研脚本。执行前进行抽象语法树策略检查，执行中限制容器权限和资源，执行后只从约定输出目录收集产物并登记为 Artifact。

代码、运行环境、输入材料、输出产物和研究对象版本由此形成完整链路。策略阻断、资源超限、运行失败、超时和产物缺失保持不同状态，用户可以区分科学结果问题与执行环境问题。

## 11. Hermes 人机协作机制

Hermes 运行在研究对象上下文内，读取当前页面、对象、字段、任务和版本状态，提供四类能力：继续当前步骤、查看证据、检查来源和比较版本；根据材料形成结构化建议并披露缺失；在高风险写入前展示变更与作用范围；提供问候、鼓励、共同思考、倾听、伸展、休息、庆祝和安静阅读等无隐藏写入的陪伴反馈。

Dashboard 使用 360 像素角色，移动或紧凑场景使用 200 像素。普通点击打开助手抽屉，桌面右键、Shift+F10 或 Menu 键打开动作菜单，移动端长按打开同一目录。菜单从角色周围空白展开，选择后先关闭，再执行角色反应和一条从口部发出的短句。编辑、输入、差异、审阅和审批场景默认安静，用户可选择紧凑尺寸、原始尺寸或安静反应。

这套机制维持页面、任务、证据和审批之间的上下文连续，同时不扩大 AI 写入权限。动效只表达来源、回应和结果，遵守 reduced-motion；Live2D 不可用时保留同尺寸静态降级。

## 12. AI 治理、权限与安全

AI Gateway 统一模型提供方和调用记录。AI 输出保存提供方、模型、时间、输入范围和模板版本。普通读取和建议可直接展示；草稿写入需要预览；删除、合并、权限变化和发布需要明确确认；更大作用域可采用批量预览、限定授权和撤销边界。所有权限检查在服务端执行。

平台还包括邀请码和邮箱验证、工作区隔离、RBAC、速率限制、配额、审计日志、恶意文件检查、解析隔离、生产网络分段、不可变发布目录、数据库备份和回滚标记。真实 Secret 不进入仓库，生产数据服务不直接映射公网端口。

## 13. 状态与异常处理

材料导入区分等待、处理中、需要复核、已确认、可重试失败和永久阻断；沙箱任务区分策略阻断、资源超限、运行失败、超时和产物收集失败；发布区分内容缺失、权限不足、许可未声明和基础设施故障。

前端在错误发生位置提供说明、重试、保存草稿或定位问题的入口。异步任务可依据任务 ID 在刷新后继续查看。关键写入使用幂等或版本条件，减少重复提交和并发覆盖。

## 14. 可进一步检索和拆分的技术点

1. 带来源片段、输入范围、模型信息和人工确认状态的结构化研究对象生成方法。
2. 长期研究对象身份、不可变版本、审阅锚点、Artifact、许可和引用的协同方法。
3. 面向 AI 代理副作用的分级预览、确认、作用域授权和撤销方法。
4. 异构科研材料在无网络、无 Secret、资源受限环境中的隔离解析及可追溯写回方法。
5. 科研脚本的策略检查、容器隔离、资源限制、输出收集、Artifact 登记和版本关联方法。
6. 同时绑定长期对象与提交时版本、字段、证据的持续协作审阅方法。
7. 不复制或改写研究对象事实身份的学术策展叠加方法。
8. 上下文感知科研伴侣的桌面右键、键盘、移动长按共享动作目录和风险审批方法。

正式申请应避免只描述界面外观，需要把输入、状态、处理步骤、约束条件、输出和可验证技术效果写入权利要求。

## 15. 技术效果

- 材料、研究叙事、证据和版本使用同一对象身份，减少跨工具复制导致的来源丢失。
- AI 建议与人工确认分离，持续显示缺失、推断和待确认状态，降低模型内容被误当事实的风险。
- 不可变版本和确定性差异为引用、审阅、更正和复现实验提供明确锚点。
- 隔离解析和沙箱执行限制网络、Secret、权限和资源，缩小不受信任文档或代码的影响范围。
- 审阅锚定对象、版本、字段或材料，研究继续演化后仍能还原意见产生时的上下文。
- Hermes 将导航、任务、证据和审批放在同一上下文内，减少寻找下一步的成本，同时不扩大 AI 权限。
- 公开页面兼顾连续阅读与深层验证，普通读者和专业复核者使用同一入口。

## 16. 当前实现与边界

截至 2026 年 8 月 25 日，平台已完成身份与工作区、RBAC、审计与配额、研究对象与 SDF、Artifact、版本与差异、协作与审阅、Hermes 审批、发布与公开页、沙箱任务、受控解析、对象存储、生产部署和备份等基础能力。非 Landing 页面已统一为暖纸阅读与研究页边体系，Hermes 使用 360/200 像素尺寸、右键/键盘/长按入口和口部短句反馈。

搜索包和共享 UI 包仍有占位能力；真实账号端到端纵向验收、更多科研格式、检索排序、机构级治理和规模化性能属于后续工作。本文不把规划能力写成已完成事实。

## 17. 术语

| 术语 | 定义 |
|---|---|
| Research Object（RO） | 具有长期身份、结构化内容、材料、版本、协作和公开记录的研究对象 |
| SDF | Problem、Insight、Method、Results、Limitations、Reproducibility 六节点研究叙事 |
| Artifact | 论文、笔记、图片、数据、代码、运行输出等可追溯材料 |
| Hermes | 运行在研究对象上下文中的 AI 研究伴侣与任务入口 |
| 不可变版本 | 保存后不被静默回写、可独立引用和验证的对象快照 |
| Provenance | 内容或材料的来源、处理过程、生成信息和确认记录 |
