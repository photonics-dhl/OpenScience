PRODUCT & IMPLEMENTATION REVIEW

让一篇论文，
成为看得懂的故事。

从全文理解出发，设计读者的理解顺序，再选择图片与表现方式。最终交付是一段科学准确、清晰而美观的视觉叙事。

读者没有读过论文，
也能说出它的核心思想和关键点。

本轮先完成图片。单张、多张、论文原图与生成示意按表达需要组合；视频以后沿用这条叙事。

这是一份离线审查文档。页面交互只用于阅读与记录意见，不调用模型，不修改论文，不提交发布。
交付目标完整链路媒体选择读者体验如何落地实施顺序审查意见
THE DELIVERABLE

先决定要讲清什么。

“上传成功、出图成功、发布成功”描述的是工程结果。产品是否完成，取决于读者理解了什么，以及表达是否准确、可读、美观。

研究什么问题？
核心想法是什么？
有什么关键发现，
在什么条件下成立？

这些是组织内容时要回答的问题，不是每篇论文必须套用的四格模板。理论、实验、方法、综述各有适合的解释结构。

先区分领域背景与本文贡献，再决定读者需要哪些解释。图数来自信息结构；风格来自主题与偏好；构图、文字与配色共同帮助理解。

默认面向“具备目标领域基本背景、尚未读过本文”的读者。用户可在 Hermes 中要求更通俗或更专业；不默认要求完全没有专业背景的人理解所有推导。

最终交付包含

  1. 一条明确主旨：读者应该带走什么认识。
  2. 一张图，或一组有前后关系的图片；每张承担一个清楚的解释任务。
  3. 可见的标题、短说明和必要术语解释；无需翻回论文寻找基本上下文。
  4. 可按需查看的原文来源与条件；清晰区分解释性示意和真实数据。

这次原图反馈意味着什么

Fig.1 原样展示保留了符号、分图和论文式图注，却没有告诉新读者为什么要看它、它与全文核心思想有什么关系。

原图可以成为素材，也可以在恰当的说明下成为成品的一部分。需要补的是它承担的叙事角色、读图顺序与解释设计。

当前公开版本保留历史；改进稿在新私有版本制作，质量认可后再形成新的公开版本。

01取得全文与来源 复用已有

输入与处理

用户上传 PDF。现有 Artifact、解析/OCR 与 SourceMap 保存原文件、页码、段落、图表和引用的可追溯关系。

交给下一步

完整、可读的原文与来源定位。原图以“来源素材”登记，不因提取成功就自动成为公开核心图。

用户看到什么

同一研究中的处理进度；确有公式或页面不可读时，指出位置及需要补充的资料。

失败如何处理

保留已上传原件与已完成工作，区分解析失败和论文没有报告。长论文超限先阻断说明原因，不让局部解析冒充全文理解。

现有入口：routes/ingestion.ts → ingestion-parser.ts → parsers/cascade-orchestrator.ts
已知缺口：第三篇在全文分析前触发 120000 字符上限；保留来源标识的分节处理尚需实现，不能直接提高上限。
02理解并确认科学内容 复用并补接上下文

输入与处理

Hermes 使用现有全文理解、六维凝练、Claim/Evidence 与科学审阅，提取问题、方法或思想、发现和限定条件。

交给下一步

用户确认的科学内容：正文作为整体导航，Claim 与完整原文作为每个陈述的证据。未经确认的中间输出不能成为新事实。

用户可以修改

在现有正文与 Hermes 对话中纠正“论文究竟在说什么”。确认后进入图片叙事，不要求再手填一套论断表。

失败如何处理

对有争议、部分成立或缺证的结论保留状态和条件。缺少关键内容先修上游；不能用更漂亮的画面掩盖理解错误。

现有：extractor.ts / skills/paper-analysis.ts / scientific-critical-thinking.ts
补接：核对当前确认版本的全文凝练如何进入分镜；当前 planner 主要收到已选 Claim，不能将单一 Claim 当作整篇论文的充分代表。
03组织整篇论文的叙事 本次核心补齐

输入与处理

当前确认版本的全文凝练、相关 Claim/原文、用户读者定位与偏好，进入现有分镜科学规划调用。先决定全文主旨，再安排读者的理解顺序。

交给下一步

主旨、目标读者、按顺序排列的画面。每个画面回答：读者要明白什么，为什么需要这张图，与前后图有什么关系，有哪些证据。

用户看到什么

Hermes 给出可读的叙事草稿与推荐图数及理由。例如“先让读者理解问题，再解释核心关系，最后说明结论与边界”；内容按论文本身变化。

用户可以修改

“太专业”“先讲结论”“这张不必要”“这里需要原图”。沿现有分镜修订入口调整；确认清晰的制作范围后才开始出图。

拟改：workspace-guide.ts → illustration-planner.ts → StoryboardDocument
把“默认一个局部关系”改为“整体叙事、逐图聚焦”。复用同一次科学规划的结构化输出，随后仍走原美术规划与科学审阅；不另加整篇论文重分析模型或独立叙事服务。
单图保持清楚的科学域与关系，整组图完成全文解释。若已确认材料不足以覆盖核心思想，应返回具体缺口，而不是强行凑出一套图。
04设计逐图表达 调整现有规划

科学内容先定

沿用 message、subjects、encoding、labels、constraints 与原文依据。先定义箭头、颜色、坐标和术语表达什么，再进行视觉设计。

艺术设计随后

使用已安装并被 Hermes 消费的设计 Skill，规划视线顺序、主体尺度、留白、文字层级与材质。全组统一科学角色的配色与术语。

媒体在这里选择

适合的原图配解释，机制采用生成示意；定量结果需要真实数据和适用的确定性渲染。图片数量不按原文图号机械对应。

审核与修改

现有科学审阅同时核对主旨、逐图陈述、标题与说明。艺术修订保留科学字段；改变关系、条件或标签含义时回到科学规划。

拟改：illustration-planner.ts / illustration-review.ts / installed-media-skills.ts / 项目配图 Skill
科学关系不为风格改变。全文叙事使用有序 scenes；原 figurePlan 保留为逐原图专项请求，不让旧“reuse 在前”规则支配新的读图顺序。
05制作所需图片 复用执行器

生成示意

已审画面简报直接进入现有服务器 Chat 图像 provider。实际传入授权参考图，保留任务和来源关联，不让下游自由改写科学关系。

原图使用

保留原始来源；读者标题与解释进入叙事成品。裁切、强调或重组需要清楚的设计与来源保留，不能修改数据含义。

控制成本

先完成叙事，再制作一张能代表整组设计的必要图片。确认方向后制作余下需要的场景；仅重做受影响部分，已认可图不默认重画。

处理异常

沿现有 task/checkpoint/spool 回收结果。状态不确定先查原请求，已完成导出优先恢复；连续失败查原因，不盲重发或切 provider。

现有：scene-image.ts → AI Gateway → infra/chatgpt-browser → storage → presentation asset
本机 codex-chatgpt-web 用于 Codex 与 Pro 的开发协作；正式用户生图由服务器 provider 执行。两条桥的权限、登录和结果独立判断。
06审阅实际成图与整组叙事 补齐成品验收

看实际图片

按真实展示尺寸查看构图、中文与符号、科学关系和来源条件。模型接受简报不等于画出的图正确，更不等于美感已认可。

看整组故事

脱离论文检查：读者能否复述核心思想和关键点，图与图是否承接，背景知识是否被误当作本文创新，必要限制是否可见。

用户可以修改

直接对着成图向 Hermes 反馈。构图不合意走艺术修订；解释不清或顺序不对回叙事；科学错误回科学规划，保留前一版。

通过后得到什么

经用户认可的成品及其读者标题、说明、顺序。复用现有批准状态与操作，不新造评分体系或额外自动审美模型。

首批由人工实际看图与用户判断完成验收。没有验证的成图审阅自动化保持“未实现”，不承诺系统能自动保证读者理解。
07编排并发布版本 补顺序与说明保存

发布前看到什么

所选的已批准成品，按叙事顺序连同标题、短说明完整预览。来源素材、失败候选与内部制作信息留在私有工作区。

同一次发布保存

在既有 publication snapshot 中保存发布媒体、读者文本和顺序。用户可确认删选及次序；删图后需要重看是否仍能讲完整。

权限与一致性

沿既有事务核对同研究、同版本、批准状态与资产身份，防止旧预览覆盖新内容。公开页只能读取这一版保存的内容。

旧版如何处理

新字段可选，旧快照继续按原规则显示。修订通过新私有版本再发布，旧公开 URL、图片和来源记录不改写。

拟改：ResearchPublication.tsx / publish.ts / research-record-snapshot.ts / version-history.ts / routes/research.ts
当前选择参数主要表达集合；必须明确保存顺序和读者说明。不能在公开请求时临时读取可能已变更的私有分镜。
08读者独立阅读与反馈 补展示消费

公开页阅读顺序

一句话贡献 → 核心画面 → 有序图片与逐图解释 → 凝练正文 → 按需展开原文与来源。首图让读者迅速理解主旨。

每张图传递什么

具体标题说明本图的意义；短说明解释必要符号与关系。多图有当前位置与前后操作，移动端可以完整读图和查看原尺寸。

产品保持简洁

提示词、task ID、内部审核过程不进入阅读主屏。原始证据可追溯，不要求读者先打开论文才明白图意。

反馈如何回去

阅读者提出不理解之处后，作者在 Hermes 中针对具体图或叙事修订。公开内容的变更仍通过新的版本完成。

已核实断点：ResearchMediaDeck 已支持 label/description，但 PresentationAssetGallery 覆盖为通用标题与固定提示。应消费发布快照中的读者文本与顺序；保留旧快照回退。
MEDIA FOLLOWS THE STORY

为解释选择媒介。

不会把每张论文图都重画，也不会给每篇论文固定配三张图。先看信息必须怎样表达，再决定是否制作。

论文原图 → 真实结果、必要细节或数据证据 已有复用
适合何时原始曲线、显微图、实验装置细节不能被概念图替代；原图质量足以支持当前解释。
如何成为成品围绕叙事设计标题、图注、必要标注与阅读顺序。复杂原图可作为次级证据展开；核心图承担主旨解释。原字节拷贝只完成素材复用。
生成示意 → 思想、机制与关系 已有 Chat 执行
适合何时需要将论文中的概念、关系或方法变得直观；精确数值和曲线形状不由生成模型决定。
如何成为成品把已审科学含义交给现有美术规划，选择学术、编辑或淡彩等处理。每张有叙事任务，整组在术语、视觉角色和信息层级上保持一致。
数据重绘 → 可追溯的数值表达 按能力补接
必须有什么经核对的原始数据、坐标、单位、条件，以及确实能完成该图的确定性绘图路径。没有数据就不从截图“猜”数值。
当前边界现有 generateClaimChartSvg 是 Claim 文字图，不能当作定量重绘能力。首轮优先原图加解释；具体数据重绘有需求时再核实并补接已有工具。
视频 → 时间演化与逐步解释 后续阶段
复用什么论文主旨、逐场景科学依据、画面含义、术语和旁白逻辑；从已认可图片叙事继续。
还要解决什么用时间解释真实过程，匹配动作、旁白、字幕与节奏，再审成片。现有视频路径有能力边界，不承诺任意生成视频；平移静态图不等于解释了机制。
READER EXPERIENCE

页面上的内容，随着故事前进。

下方是阅读结构示例，演示图文如何分工；不代表 Quantization 论文的科学结论或最终图片，也不固定每篇论文为三张。

先让读者抓住主旨

这篇论文带来了什么新认识？

主画面围绕一句明确贡献组织。对象、对比或关系是视觉焦点；图上短标签和图下说明共同建立上下文。

研究问题→本文关键想法→为什么重要

读者应能回答：“我知道这篇论文想解决什么，以及它提出了什么关键想法。”具体陈述须由经审全文结果提供。

再解释必要的关系

为什么这个想法能够成立？

从前一张已建立的对象继续，解释关键机制、推理、比较或方法。保留一致的术语与科学角色配色；在读到符号的地方解释它。

已知对象→关键关系→有依据的解释

读者应能回答：“我能说清核心关系，而不是只记得一个公式或漂亮图案。”支持它的原图可以按需在这里出现。

让结论有清楚的范围

我们因此知道了什么？

用最适合的媒体说明关键发现与必要条件。真实数据保留来源，定性示意不伪装成测量结果；限制条件作为解释的一部分。

关键发现＋成立条件→准确的理解

读者应能回答：“我知道这个结论意味着什么，也知道它不能被扩大解释到哪里。”

已有媒体容器可继续使用。需要改变的是传入的内容和顺序，让具体标题与读者说明取代通用的“图 N”。图中文字与图下说明必须一起经过科学审阅。

IMPLEMENTATION

在现有链路上补齐。

Hermes继续负责唯一的论文解析、全文理解与科学确认；视觉叙事是现有分镜科学规划的输出增强，艺术设计沿用原阶段。不新增论文分析器，不增加第二次全文总结调用，也不建立另一套分析结果库。下列改动补接既有生产者和消费者。

数据怎么接起来

  • 研究对象与当前私有版本是所有操作的作用域；原件、Claim 和 Evidence 沿用已有标识。
  • 现有分镜是叙事的承载位置。复用场景顺序、标题、旁白/说明和来源关联，只在现有字段确实不够时增加可选字段。
  • 成图继续关联批准的父分镜与场景。面向读者的文字独立于像素保存，审阅后随发布版本一起固定。
  • 新字段须同步 Domain parser、请求校验、任务结果、网页 DTO 与消费者；旧任务/快照不强制迁移。
  • 现有来源身份、父稿变化检测和 checkpoint 继续使用；不新增哈希、全局基线或审核平台。
