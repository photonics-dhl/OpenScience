## Task 3: 每 RO 的 AI 友好只读 API

复用既有服务提供固定版本的机器可读入口及 API 发现链接；使用现有路由风格，无需为示例路径重构。返回 schemaVersion、objectId、versionId、固定引用、SDF、Claim/Evidence、材料 manifest 和缺失状态，集合有确定顺序及明确分页/完整性说明。latest 解析固定版本；匿名仅公开已发布版本，登录用户仅有权访问版本，私有响应 no-store。不得把可变草稿伪装固定版本。

审查确认现有 Version 的 SDF/manifest 固定，但 draft Claim/Evidence 可编辑。为固定 API 保存真正不可变的提交时研究记录（必要时增加 nullable JSON 快照字段和可回滚迁移），在创建/导入确认事务内捕获，GET 不补写。后续草稿编辑不得改变已引用的快照；当前草稿图谱与固定记录明确区分。旧版本没有冻结元数据时如实返回 not_recorded，不用当前图谱冒充历史。保留现有协作与发布流程，UI 的固定记录预览与 API 读取同一份内容；不要自动发布以规避冻结问题。

权限保护来源下载；固定记录的来源解析必须使用冻结的定位，不能经当前可编辑 Evidence 行漂移。不泄露 objectKey、内部存储 URL 或隐藏版本。GET 不调用模型、不写业务记录。提供机器可读 OpenAPI/响应 Schema 和人类接入说明（请求响应、现有鉴权、错误、分页/限流、固定版本引用）；UI 提供 API 链接。冻结内容共用于版本预览和导出，私有 SourceMap 引用仅用于服务器解析。编写真实路由测试覆盖匿名/私有、固定版本稳定性、草稿隔离、来源定位稳定及缺失来源。

运行 API/domain 相关测试和类型检查；提交仅此任务代码。控制器维护文档索引与发布文档，不 push/deploy。
