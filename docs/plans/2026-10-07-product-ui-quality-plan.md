# OpenScience 全站产品界面质量计划

## 目标

把 OpenScience 从“能用的页面集合”收敛为有明确叙事、稳定层级和一致互动语言的科研产品。Landing 的主视觉与正文保持现状；本计划优化其余页面以及 Landing 与全站导航、账户入口的衔接。

## 已确认的产品叙事

- 公开区域负责探索、阅读研究与期刊；不把私有创建动作散落在公共导航。
- 登录后的第一工作面是研究桌面：真实研究列表优先，创建/导入只保留一个主动作，处理记录与手动工具按需展开。
- 研究编辑页围绕研究对象和当前产物组织；工具、证据、版本在上下文中出现。
- 使用指南邀请用户完成第一次研究动作；它是可读、可选择、可展开的研究手册，不是防御性说明书。
- Hermes 是全站共享的互动陪伴入口：桌面研究桌面保留 360px 席位，其余场景和窄屏使用一致的 120px Live2D 入口；打开后在专属区域完整展示，关闭归位。该场景策略已由用户确认，取代早先所有桌面页面默认 360px 的决定；Landing 不放浮动 Hermes。

## 页面系统

1. **公开阅读**：研究/期刊标题或真实贡献先出现，媒体与正文是视觉锚点，来源和证据按需展开。
2. **研究桌面**：可继续的研究列表和一个创建动作先出现；内部尝试与处理记录收进历史，手动管理按需展开。
3. **工作区**：全局导航、研究对象上下文、局部模式三层分开；移动端把多栏变为可切换平面，不删除能力。
4. **账户与管理**：身份或管理任务先出现，设置、API、期刊管理按功能分组；表单反馈在动作附近可见。
5. **身份页**：登录/注册优先完成身份动作，Hermes 与品牌负责建立关系，不和表单争夺第一焦点。

## 共享视觉规则

- 延续冷白、墨色、青绿色、学术编辑字体与真实科研图；用留白、字号和规则线建立层级，减少同构卡片。
- 页面容器最大约 1280px；长文正文控制在舒适阅读宽度；页头不遮挡内容。
- 每个首屏只有一个主标题、一个主任务和一个视觉锚点。次要操作进入上下文菜单或局部工具栏。
- 控件统一 44px 最小触控尺寸、明确 hover/focus/active/disabled/loading/error/empty 状态。
- 动效只表达进入、选择、状态变化或展开；160–450ms，尊重 `prefers-reduced-motion`，不持续制造外围噪声。

## 分批实施

### 第一批：共享骨架与研究桌面

- 统一 ShellHeader 的层级、当前路由、账户工具和窄屏导航。
- 统一页头、主内容宽度、背景、选择色、焦点环和表面深度。
- 打磨研究桌面的首屏阅读顺序、继续研究、创建/导入、Hermes 任务和研究库。
- 保持 Hermes 统一尺寸、单一视觉对象和不遮挡内容的锚定规则。

### 第二批：公开探索、指南、期刊与研究阅读

- 用真实研究对象、期刊内容和媒体建立公开页面锚点。
- 保留指南的“资料→理解→表达→公开”流程，但减少文字堆叠，增强选择与展开反馈。
- 统一目录、阅读页、来源/证据和公开版本的页头与局部导航。

### 第三批：编辑、账户、开发者、期刊管理与异常状态

- 统一工作区三平面、编辑器、Hermes 处理状态、账户工具和管理控制台。
- 完成空、加载、失败、权限、保存反馈及长标题/中文布局。

## 验收

- 真实导航路径：公开首页→探索/指南/期刊，登录→研究桌面→创建/继续研究→Hermes/编辑器。
- 视口：1440、1280、1024、768、390、375；无横向溢出，主标题与主动作首屏可见。
- 互动：键盘焦点、账户菜单、导航当前态、主动作、Hermes 展开/关闭、减少动态效果。
- 状态：加载、空、失败、成功、禁用和长内容；检查控制台错误、布局跳动和图片尺寸稳定。
- 结果分开记录为候选、部署、实际观察和用户确认，不以构建通过替代视觉验收。

## 当前执行边界

本计划不修改 Landing 主视觉，不引入未经验证的新依赖，不使用通用设计系统覆盖既有产品语汇。设计系统文件只记录已批准的 OpenScience 决策与页面例外。

## 2026-10-08 构图修订

本轮采用 Product Design 截图审查，并实看 [Linear](https://linear.app/) 与 [Apple MacBook Pro](https://www.apple.com/macbook-pro/) 的当前网页。借鉴主标题与真实产品的比例、主次明确的阅读顺序和辅助信息退后；不移植品牌素材。研究内容、作者、公开版本与完整科学图保持真实。

私有页面沿既有 2026-10-03 决定，只在官网 HTTPS 或隔离测试环境验收；localhost 公开 API 反代不能作为正式账号登录入口。截图观察、构建与用户审美认可分别记录，登录限制不取消研究桌面、编辑器、账户和管理页的后续工作。

| 页面 | 构图与阅读重点 | 本轮修订 |
|---|---|---|
| 指南 | 邀请进入研究；真实论文是可阅读的成果样张 | 主标题与论文标题分级；纸面样张、完整科学图、邻近作者与图注；竖向场景索引在窄屏变为横向选择 |
| 探索 | 搜索与发现具体研究 | 移除贯穿页面的空色带；无图研究用标题／贡献分栏，有图研究完整展示；手机短说明与紧凑角色同排 |
| 期刊目录 | 期刊身份、领域与收录范围 | 期刊名与说明组成一张目录跨栏；检索保留在目录上沿；不编造封面与统计 |
| 登录／注册 | 身份表单是主任务，品牌邀请提供情境 | 邀请文案先于角色；表单与说明共享垂直节奏；统一纸面边界与输入反馈 |
| 研究桌面 | 正在推进的研究先被看见 | 研究标题、下一步动作、任务记录分级；Hermes 回到右侧专属 360px 区域，窄屏与说明并排 |
| 设置／个人主页 | 身份、研究作品与可操作偏好 | 统一纸面；额度数字与字段标签分级，研究标题更易扫读；角色使用页面预留区域 |
| 编辑与研究详情 | 阅读成果与连续写作 | 移除全站样式叠加的外层纸框；调整贡献段落与媒体比例；共享研究页边承接角色，对话内避免角色覆盖输入 |
| 研究材料 | 已有文件与添加材料先出现 | DOI 关联退为可展开的次级工具；全部导入历史在独立展开区域保留，避免重复文件名占满首屏 |

已否定的尝试：把论文样张整块涂为深青色。独立截图批评指出该容器抢过了科研图；修订回纸面、细线与真实内容的对比。照片、插画本身的风格不能靠 CSS 改成另一种科学表达。上述修订仍是候选审美，整站剩余工作和用户接受状态由 canonical CURRENT 汇总。

本轮后续发现官网 HTTPS 的既有账号会话可用，已实际从站内进入研究桌面、设置、个人主页、编辑器、概览和文件；没有提交研究、认证、额度或发布修改。桌面构图另做了浏览器临时对照，之后撤销。其截图只用于判断比例，不能替代候选代码上线后对 Live2D、滚动、焦点与窄屏的验收。

角色搬入对话的独立审查发现：切换 React portal 容器会重建渲染器，196px 紧凑容器放进 120px 页边会溢出。候选保留稳定的渲染容器、适配页边宽度，对话内不保留无效的“再次打开”Tab 焦点。后续独立审查另发现切页复用旧 anchor 几何；已用 pathname 与实际元素身份同步过滤，相关运行观察未完成前不称已验收。

## 场景式助手与减负修订

实看 [GitHub 上下文助手](https://github.blog/changelog/2026-05-18-ask-questions-in-context-with-copilot-on-web/) 与 [Notion Agent](https://www.notion.com/help/notion-agent) 的官方界面示例：保留内容上下文，小入口打开专属面板，个性化角色服务于工作。OpenScience 保留 Live2D，不照搬它们的视觉资产或品牌。skills.sh 的 high-end-visual-design 固定双层卡框与大留白模板不适合本次收拢任务，未安装；采用现有 Impeccable 的 distill/shape 与项目审美协议。Figma 本轮仍返回 `UNAUTHORIZED / Reauthentication required`；用户正在重新认证，未声称进行了新画布操作。

候选已移除桌面重复的继续研究卡与下方重复创建区，保留一个研究集合、一个导入主动作、一个 Hermes 席位；过程记录与手动工具默认折叠，归档移到条目菜单。官网实际内容只作临时 DOM/CSS 构图对照，随后恢复；对照不能证明新 React、键盘焦点、窄屏或 WebGL 生命周期已经通过。

独立审美批评继续否定了第一版对照中抢眼的 Hermes 白框、远离主任务的创建按钮与难区分的版本。第二次对照移除助手白框、收紧说明与角色、把动作菜单放回角部；创建与标题归为同组，版本/状态形成固定次级轴。临时样式已从官网撤销，截图只留 ignored `tmp/ui-art-20261008/`。通用 Shell 不再用独占140px空行安置入口，采用同样的紧凑角部入口；有页面席位时优先归位。创建页入口也接入现有完整助手，打开本身不发起任务。

从官网“账户工具”继续实际进入我的期刊、期刊审核与开发者 API。发现六个期刊管理页把研究桌面误标为当前栏目，候选已统一归到期刊；我的期刊空状态改为编辑式邀请、明确的申请/浏览入口与页册线稿，并补齐中英翻译。实际账号没有加入期刊，故未假装验收有内容的期刊编辑工作台。平台审核数据只读观察，没有审核申请、开通额度或改变运营状态；开发者文档也未发送业务写请求。这些候选仍须运行后验收。

空间只读核查没有可靠的测试来源标记。部分重复 PDF 记录仍关联真实论文，五个研究对象中还有已公开历史，故未按名称删除任何记录。现有可恢复归档入口为 `/api/trash`，`packages/domain/src/trash/trash.ts` 的 `moveToTrash/restoreTrash/taskIsAdopted/taskHasProtectedReference/publicAssetReferences` 已保护采用成果和公开引用。清理已识别测试数据沿用此流程，不新增猜测分类字段。

用户要求将技术检查留在系统内部，只点评最终结果并决定采用。前端这轮已降低过程记录权重；完整自动执行仍须与 Domain/Native 的真实状态衔接。准确协调点为 `packages/domain/src/agent/research-run.ts` 的 `confirmHermesSourceReview` / `authorizeHermesGenerationGrant`、前端 `IngestionClaimReview.tsx` / `HermesMediaReview.tsx` 及 `packages/domain/src/assets/native-image-review.ts`。技术合格、用户采用、付费生成授权和公开发布分别沿用已有合同；本轮不修改其他 owner 的后端状态，不伪造通过或自动发布。

## Native 视频前端合同衔接

已合并总控稳定基线 `c3029264`，保留本线三批 UI 提交。前端沿用服务端 `canGenerateSceneImage`、`canGenerateVideo` 和有序 `videoFrameAssetIds`，不再把 Native 草稿的人工采用状态误当成制作资格。新视频分镜请求保留 `narrative: true`、明确父稿与可选单幕修订范围；图像场景索引与视频修订索引分开。真实对话分支中的折叠制作设置可切换媒介与修改范围，主界面仍围绕结果和对话。未知提交按原 payload/key 恢复；图像与视频的待续请求分别保存，避免覆盖。旧非 Native 手动流程暂保留原有已采用帧排序，资格仍由服务端决定；Native 缺少帧投影时不猜测。

独立 High 审查发现的范围混淆、对话分支漏渲染控件均已修复；4 个定向测试文件共23项通过，Web构建 exit0。测试覆盖实际组件注册的确认动作，但没有冒充浏览器验收。普通用户“由论文开始制作视频”的新入口暂未接入：待后端稳定提交同时提供 `researchRunDraft.output` 与 existing-run 的 `output=video` 精确查询，才能复用既有来源和幂等恢复，避免把旧图像请求升级为视频授权。UI owner 本轮未部署、重启服务器或发起付费制作；新版期刊草稿工作台的并行交付在总控集成，不从本树旧文件回盖。

期刊稳定基线 `a55abec4` 随后合入本线：旧 processing 路径按新版规则跳到统一草稿工作台；目录保留完整分页、筛选、排序、权限和账户操作，条目沿新版仅展示期刊身份与出版商，不恢复长简介。UI 的分栏排版、翻译标题与场景式 Hermes 入口保留。管理工作台、来源权限矩阵、目录操作与 SiteHeader 与总控源无差异；4 个相关前端测试文件18项通过。合并只在 UI 树进行，没有修改 canonical 或线上版本。
